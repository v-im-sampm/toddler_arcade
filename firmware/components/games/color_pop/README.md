# Color Pop (G01)

Spec: [games/color_pop.md](../../../../games/color_pop.md) and [v2/games/color_pop.md](../../../../v2/games/color_pop.md).
Status: game logic ported from `v2/reference/quality_bar.html`. It runs on the vendored
[PixelRoot32](../../pixelroot32/VENDORED.md) engine, on the device and in the desktop simulator.

## Runtime (`pr32/`)
- `ColorPopStage` (public): creates the engine once (`init_runtime`), then on each UI tick runs
  `Engine::run()`. Touch goes in through the engine's `TouchEventDispatcher`, and the frame and
  dirty rectangles come out to the arcade's single `lv_image`. The frame buffers (3 × 150 KiB,
  PSRAM) exist only while Color Pop is open. If they can't be allocated, the arcade shows a plain
  sea and taps still reach the game.
- `ColorPopScene`: a `pixelroot32::core::Scene`. It draws `ColorPopGame`'s public state with baked
  4bpp sprites (`color_pop_sprites.cpp`, generated by `tools/gen_color_pop_sprites.py`) and engine
  primitives. The static background is drawn once and restored span by span.
- `FrameSurface`: the engine's `DrawSurface`, a 320×240 RGB565 surface that tracks per-band spans
  and diffs them on present.
- `ColorPopAudio`: the score on the engine's APU. AudioFeedback pulls it on the audio task through
  `ISceneAudio`, after the volume ramp and limiter, so it stays muted until a parent opts in.

## Behaviour
- INTRO (1.2 s, any input skips) → PLAY → CELEBRATE (1.5 s) → PLAY with a new round.
- Each round shows 2 bubbles, growing to 4. Colours are distinct, positions are shuffled over 6 fixed 72×72 slots, and the target never repeats back-to-back.
- Each colour has its own pattern (`pattern_for`): RED heart, BLUE wave, GREEN leaf, YELLOW star. The target badge at the top centre shows the requested colour and pattern, so the game works with audio off.
- A wrong bubble wiggles, the target hint glows and the prompt replays. Nothing is lost, and there's no failure state.
- Input during CELEBRATE is ignored, which makes repeated taps and voice-during-animation safe.

## Input map
| Action | Touch | Voice intent |
|---|---|---|
| Choose colour | tap bubble | RED / BLUE / GREEN / YELLOW |
| Hear request again + hint | tap target badge | AGAIN, HELP |
| Home | Home button (SceneManager) | BACK (SceneManager) |

## Tests
`color_pop_test` (host only) covers:
- layout size and spacing
- intro and prompt behaviour
- round invariants and growth
- randomised and deterministic layouts
- voice/touch equivalence
- gentle wrong answers
- input during celebration
- audio disabled
- Home pressed mid-animation
- playing through the `SceneManager`

`color_pop_pr32_test` (host only) runs the real engine and covers:
- the first frame is full and painted (sky, sea, sand, Home key);
- every bubble shows its own colour;
- incremental frames are byte-identical to a full redraw;
- engine touch events reach the game (a single press pops; a held finger doesn't repeat);
- APU cues sound at sane levels, idle is silent, and `stop()` silences.
